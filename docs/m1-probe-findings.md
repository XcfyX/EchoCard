## 1. 设备识别（重要修正）

| 项目 | 规格书假设 | 实测（DJI Mic 2 TX2） |
|---|---|---|
| USB VID | `0x2CA3` | **`0x10D6`**（Actions 半导体 USB 桥接芯片，PnP 父设备 `USB\VID_10D6&PID_B00B\0123456798AB`） |
| USBSTOR 串 | — | `USBSTOR\DISK&VEN___DJI&PROD_WIRELESS_MIC_TX2&REV_0.01\0123456798AB&0` |
| 卷标 | — | 空（无标签） |
| 挂载形态 | UMS 盘符 | ✅ UMS 盘符（发射器插电脑） |

**结论**：认亲采用四重信号联合判断 —— `.echocard_source` 标记文件 ∨ VID 候选
（`0x2CA3` + `0x10D6`）∨ USBSTOR 厂商/产品串含 DJI ∨ 已绑定序列号记忆。
未认亲卷一律「记录已忽略，绝不触碰」。

## 2. 设备目录结构与命名

- 根目录：`DJI_Audio_001`（带序号后缀，规格书写的 `DJI_AUDIO` 需通配匹配）
- 系统目录：`System Volume Information`（隐藏，扫描直接跳过，绝不进入）
- 文件命名：`DJI_42_20261122_212830.WAV` —— **文件名内嵌权威录制时间戳**，
  序号在设备清空后会复位（实测存在 DJI_16/DJI_26/DJI_36 等重复序号），
  时间归类必须优先解析文件名而非序号。

## 3. 音频格式实测

- `pcm_f32le`（32-bit float）/ 48000 Hz / 单声道 ≈ 1.5MB/8.17s（~1.9 MB/分钟）
- M2 转码目标 16kHz 单声道 WAV → Opus 压缩的输入格式以此为准

## 4. 风险项（已在状态机中防护）

- Reddit 反馈 DJI 存在零字节坏文件 → 状态机对 0 字节：标记失败、保留源文件、绝不删除
- 文件删除只允许「拷贝 + 大小校验 + SHA-256 落库全成功 + 红线开关开启」后对单个文件执行
- 设备中途断连：终止本次导入，已导入部分安全落库，未完成文件留在设备上
